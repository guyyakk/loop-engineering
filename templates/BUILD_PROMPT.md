# Prompt: Build loop

ใช้ข้อความนี้หลังสร้าง task spec แล้ว

```text
ทำงานตาม task spec ที่ [พาธไฟล์ spec]

เป้าหมายคือทำให้ acceptance criteria ทุกข้อผ่านด้วยหลักฐานจริง

ก่อนแก้โค้ด ให้สรุป outcome, ขอบเขต, เกณฑ์รับงาน, ไฟล์ที่คาดว่าจะเปลี่ยน และคำสั่งตรวจที่เหมาะกับ repository นี้
จากนั้นทำ implementation ที่เล็กที่สุดที่ตอบโจทย์ และรัน validation ที่เกี่ยวข้อง

หากการตรวจไม่ผ่าน ให้แก้ตามผลที่พบแล้วตรวจซ้ำ โดยแก้ได้สูงสุด 3 รอบ
อัปเดตตาราง Validation plan และ Loop log ใน spec ทุกครั้ง ใช้คำสถานะตามตารางใน template เท่านั้น
ส่วนที่ตรวจเองไม่ได้ (บัญชีจริง, key จริง, สิทธิ์ browser/OS, ติดตั้งโปรแกรม) อย่าเสียรอบไปพยายาม ให้เขียนขั้นตอนไว้ในหัวข้อ "ตรวจโดยคน"

ห้าม merge, deploy, เปิด PR หรือแก้ข้อมูลจริงเอง
ก่อนจบ: ตั้ง Status: ของ spec, คัดลอกข้อตรวจโดยคนไปที่ docs/HUMAN_CHECKS.md, และเพิ่มแถวใน docs/RETRO.md ถ้าครบ 3 รอบ / ติด blocker / มีข้อตรวจโดยคน / Not run ด้วยเหตุผลเดิมซ้ำจาก spec ก่อน
แล้วรัน node scripts/check-docs.mjs ให้ผ่าน
แล้วสรุปไฟล์ที่เปลี่ยน, ผลตรวจราย acceptance criterion, ความเสี่ยงคงเหลือ และสิ่งที่ต้องให้คนตัดสินใจ
```
