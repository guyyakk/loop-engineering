# Task: OpenLoops 7 — ดึงเวลาไม่ว่างจาก Google Calendar

> spec ย่อยที่ 7 ของ [2026-09-24-openloops-0-epic.md](2026-09-24-openloops-0-epic.md) (v2) ต่อยอดจาก [spec 6](2026-09-25-openloops-6-backup.md)

## Outcome

เวลาว่างของแต่ละวันคิดจากปฏิทินจริง ผู้ใช้ไม่ต้องกดเวลาประชุมเอง: เชื่อม Google Calendar ครั้งเดียว แล้วหน้าวันนี้ บอร์ดสัปดาห์ ปิดวัน และทบทวนสัปดาห์ ใช้ช่วงไม่ว่างจากปฏิทินในเวลางานทันที โดยแอปเห็นแค่ "ช่วงไม่ว่าง" ไม่เห็นชื่อหรือรายละเอียดนัด

## Context and scope

- In scope:
  - ส่วน "Google Calendar" ในการตั้งค่า: กรอก OAuth Client ID (มีวิธีสร้างทีละขั้น), เชื่อมต่อ, ซิงก์, ตัดการเชื่อมต่อ, สถานะ
  - ขอสิทธิ์ด้วย Google Identity Services (token model) scope `https://www.googleapis.com/auth/calendar.freebusy` อย่างเดียว
  - เรียก `POST https://www.googleapis.com/calendar/v3/freeBusy` ของปฏิทินหลัก ช่วงสัปดาห์นี้และสัปดาห์หน้า
  - คำนวณนาทีไม่ว่างในเวลางานต่อวัน เก็บต่อวันใน IndexedDB แล้วใช้คำนวณเวลาว่างทุกหน้า
- Out of scope: จองเวลาทำงานลงปฏิทิน (ต้องใช้สิทธิ์เขียน แยกเป็น spec ภายหลัง), หลายปฏิทิน/ปฏิทินที่แชร์, Outlook/iCloud, sync ผ่าน server, แสดงรายการนัด
- Constraints:
  - ไม่มี server: token อยู่ในหน่วยความจำเท่านั้น ไม่บันทึกลงดิสก์ ไม่ใส่ในไฟล์สำรอง ไม่ log
  - เก็บเฉพาะจำนวนนาทีไม่ว่างต่อวันและเวลาที่ซิงก์ ไม่เก็บเวลาเริ่ม-จบ ชื่อ หรือรายละเอียดนัด
  - popup ขอสิทธิ์ต้องเปิดจากการกดของผู้ใช้เท่านั้น; ไม่ได้ตั้งค่า/ไม่ได้เชื่อม แอปต้องทำงานเหมือนเดิมทุกอย่าง
  - AI ทดสอบการ login Google จริงไม่ได้ (ห้ามยืนยันตัวตนแทนผู้ใช้) จึงทดสอบด้วย Google API จำลอง แล้วให้ผู้ใช้ทดสอบของจริง

## กติกา

- นาทีไม่ว่างของวัน = ความยาวรวมของช่วงไม่ว่าง หลังรวมช่วงที่ซ้อนกัน และตัดเฉพาะส่วนที่อยู่ในเวลางาน (เวลาเริ่มงาน ถึง เวลาเริ่มงาน + ชั่วโมงทำงาน) ของวันนั้นตามเวลาเครื่อง
- ช่วงไม่ว่างที่ข้ามวันถูกแบ่งให้แต่ละวันตามส่วนที่ทับเวลางานของวันนั้น
- เวลาว่างของวัน = ชั่วโมงทำงาน − นาทีจากปฏิทิน − ธุระอื่นที่กดเอง − เวลาเผื่อ; เมื่อวันนั้นมีข้อมูลปฏิทิน ปุ่มประชุมที่กดเองเปลี่ยนชื่อเป็น "ธุระอื่นนอกปฏิทิน" เพื่อไม่ให้นับซ้ำ
- ซิงก์อัตโนมัติ (ไม่เปิด popup) เมื่อเปิดแอป ข้ามวัน หรือกลับมาที่หน้าต่าง ถ้า token ยังไม่หมดอายุและซิงก์ครั้งล่าสุดเกิน 15 นาที; token หมดอายุ → ขึ้นปุ่ม "ซิงก์อีกครั้ง"
- ข้อมูลปฏิทินที่ซิงก์เกิน 1 วันแสดงคำเตือนเล็ก ๆ
- ตัดการเชื่อมต่อ = เพิกถอน token + ลบนาทีจากปฏิทินที่เก็บไว้ทุกวัน (ธุระที่กดเองยังอยู่)
- ข้อผิดพลาดแปลเป็นภาษาไทย: ปิด popup/ไม่อนุญาต, Client ID ผิดหรือ origin ไม่ได้ลงทะเบียน, token หมดอายุ (401), ไม่มีสิทธิ์/ยังไม่เปิด Calendar API (403), เครือข่ายล่ม

## Remaining risk

- ยังไม่เคยคุยกับ Google จริง: รูปแบบ error ของ GIS (`error`/`error_callback`), การบล็อก popup และ CORS ของ freeBusy อ้างอิงจากเอกสาร ต้องยืนยันด้วยบัญชีจริง
- token อยู่ในหน่วยความจำเท่านั้น (ราว 1 ชม.) เปิดแอปใหม่หรือเกินชั่วโมงต้องกด "ซิงก์อีกครั้ง" — ตั้งใจแลกกับการไม่เก็บ token ลงเครื่อง; ถ้าผู้ใช้ออกจาก Google หรือ browser บล็อก third-party cookie อาจต้องเลือกบัญชีซ้ำ
- ถ้า Google ไม่เรียก callback เลยหลังปิดหน้าต่างขอสิทธิ์ (ปกติจะเรียก `popup_closed`) การกดเชื่อมต่อครั้งถัดไปจะได้ token แต่ยังไม่ซิงก์ ต้องกดอีกครั้ง
- เปลี่ยนชั่วโมงทำงานตอนไม่มี token: นาทีปฏิทินที่เก็บไว้ยังคิดจากเวลางานเดิมจนกว่าจะซิงก์ครั้งถัดไป (บรรทัดสถานะบอกเวลาซิงก์ล่าสุดอยู่)
- OAuth consent screen แบบ Testing: Google อาจให้ token/สิทธิ์หมดอายุตามนโยบายของโปรเจกต์ทดสอบ ถ้าเจอบ่อยต้องพิจารณา publish แอปหรือทำ server ภายหลัง

## Human decision needed
