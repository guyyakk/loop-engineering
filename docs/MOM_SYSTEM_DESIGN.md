# ระบบ MOM: จดระหว่างประชุม → สรุปอัตโนมัติ → ส่งอีเมล / LINE กลุ่ม

เอกสารนี้ตอบคำถามว่า "ควรทำยังไง" ไม่ใช่โค้ดจริง ใช้เป็นฐานก่อนเปิด task spec ใน `docs/tasks/`
เทมเพลตสำหรับกรอกระหว่างประชุมอยู่ที่ [templates/MOM_TEMPLATE.md](../templates/MOM_TEMPLATE.md)
โค้ดของเฟส 1 ที่เขียนตามเอกสารนี้แล้วอยู่ที่ [apps-script/](../apps-script/) พร้อมวิธีติดตั้งใน [apps-script/README.md](../apps-script/README.md)

## 1. สรุปข้อเสนอใน 5 บรรทัด

1. เก็บข้อมูลเป็น **ตารางบรรทัดละ 1 งาน** ตั้งแต่ตอนพิมพ์ในห้องประชุม ไม่ใช่ข้อความยาว ๆ แล้วค่อยมาแยกทีหลัง
2. เฟสแรกใช้ **Google Sheets + Google Apps Script** ไม่ต้องมีเซิร์ฟเวอร์ ไม่ต้องจ่ายเงิน ทำเสร็จได้ใน 1 วัน
3. อีเมลส่งด้วย `GmailApp` เป็น HTML table
4. **LINE ใช้วิธีสร้างรูป PNG ให้ แล้วคนเซฟไปวางในกลุ่มเอง** (ทางที่ผู้ใช้เลือก) — ไม่ต้องสร้าง LINE OA ไม่ต้องตั้งบอท ไม่ต้องเสียโควตาข้อความ และไม่มีความเสี่ยงส่งผิดกลุ่ม
5. ค่อยอัปเกรดเป็นเว็บแอปหรือต่อ LINE Messaging API เมื่อเจอเพดานจริง (ต้องติดตามสถานะงานข้ามประชุม / ต้องเตือนก่อนครบกำหนด / ขี้เกียจเซฟรูปเอง)

## 2. สิ่งที่ระบบต้องทำ (ไล่ตามเวลาจริง)

| ช่วงเวลา | เกิดอะไรขึ้น | ระบบต้องรองรับ |
| --- | --- | --- |
| ก่อนประชุม | เปิดไฟล์/ชีตใหม่จากเทมเพลต | สร้างเอกสารประชุมใหม่ใน 1 คลิก ดึงวาระค้างจากครั้งก่อนมาให้ |
| ระหว่างประชุม | ผู้จดพิมพ์: ใครทำอะไร เสร็จเมื่อไหร่ | พิมพ์เร็ว ไม่ต้องจัดรูปแบบ ใส่ชื่อ/วันที่แบบเลือกจาก dropdown |
| ปิดประชุม | กดปุ่มเดียว | ตรวจความครบถ้วน → สร้างสรุป → ส่งอีเมล + ได้รูป PNG สำหรับวางใน LINE |
| หลังประชุม | ติดตามงาน | เตือนก่อนครบกำหนด, สรุปงานค้างก่อนประชุมครั้งหน้า |

**เส้นแบ่งสำคัญ:** ขั้น "ปิดประชุม" ต้องมี **human gate** เสมอ — ให้คนกดยืนยันก่อนส่งออกภายนอก ห้ามส่งอัตโนมัติทันทีที่ปิดไฟล์ (ตรงกับกติกาข้อ 5 ใน [AGENTS.md](../AGENTS.md))

## 3. โครงข้อมูล (ใช้ได้ทั้งเฟส 1 และเฟส 2)

ออกแบบเป็น 3 ตาราง ถ้าอยู่ใน Google Sheets ก็คือ 3 ชีต — `meetings`, `action_items` และ `people` (ทะเบียนรายชื่อ ใช้ทำ dropdown และหาอีเมลผู้รับ)

**ตาราง `meetings`** — 1 แถว = 1 การประชุม

| คอลัมน์ | ชนิด | หมายเหตุ |
| --- | --- | --- |
| `meeting_id` | text | `MOM-2026-001` สร้างอัตโนมัติ |
| `title` | text | บังคับ |
| `date`, `start_time`, `end_time` | date/time | บังคับ |
| `location` | text | ห้อง หรือ ลิงก์ออนไลน์ |
| `chair`, `note_taker` | text | |
| `attendees`, `absentees` | text | คั่นด้วย `,` |
| `decisions` | text | มติที่ประชุม |
| `next_meeting_at` | datetime | ใส่ในอีเมลและปฏิทิน |
| `status` | enum | `draft` / `sent` |
| `sent_at` | datetime | กันส่งซ้ำ |

**ตาราง `action_items`** — 1 แถว = 1 งาน = 1 เจ้าภาพ

| คอลัมน์ | ชนิด | หมายเหตุ |
| --- | --- | --- |
| `item_id` | text | `MOM-2026-001-A1` |
| `meeting_id` | text | foreign key |
| `task` | text | บังคับ ขึ้นต้นด้วยคำกริยา |
| `owner` | text | บังคับ **คนเดียว** ถ้าหลายคนให้แตกแถว เลือกจาก dropdown ของชีต `people` |
| `due_date` | date | บังคับ |
| `priority` | enum | High / Medium / Low |
| `status` | enum | Open / In progress / Blocked / Done |
| `note` | text | สิ่งที่ต้องรอ หรือ blocker |

**ตาราง `people`** — `name`, `email`, `department`, `active` — เก็บอีเมลไว้ที่เดียว ไม่ซ้ำในทุกแถวงาน และทำให้ชื่อคนสะกดตรงกันทุกครั้ง

กฎ validation ที่ต้องมีตั้งแต่วันแรก (เพราะเป็นสาเหตุที่ MOM ส่วนใหญ่ใช้ไม่ได้จริง):

- `owner` ต้องไม่ว่างและต้องเป็นชื่อเดียว
- `due_date` ต้องไม่ว่างและต้องไม่ย้อนหลังกว่าวันประชุม
- `task` ต้องไม่ว่าง — ตั้งใจ **ไม่บังคับความยาว** เพราะการบล็อกไม่ให้บันทึกเพราะเขียนสั้นไปทำให้คนจดหงุดหงิดระหว่างประชุม ถ้าอยากกันคำกำกวมอย่าง "ตามที่คุย" ให้ตั้ง `MIN_TASK_LENGTH` แล้วระบบจะเตือนแทนการบล็อก

ถ้าข้อไหนไม่ผ่าน ให้ปุ่มส่งขึ้นเตือนและ **ไม่ส่ง** จนกว่าจะแก้

## 4. สถาปัตยกรรมที่แนะนำ

### เฟส 1 — Google Sheets + Apps Script (แนะนำให้เริ่มที่นี่)

```
Google Sheet (2 ชีต + dropdown)
   └─ เมนู "MOM" → กด "ตรวจและสร้างสรุป"
        ├─ validate()      ตรวจฟิลด์บังคับ
        ├─ buildSummary()  → HTML + ข้อความสั้น
        ├─ GmailApp.sendEmail()   → ผู้เข้าร่วม + CC
        └─ buildImage()           → PNG เก็บใน Drive + ลิงก์ให้เซฟไปวาง LINE
```

ข้อดี: ไม่มีเซิร์ฟเวอร์ให้ดูแล, ทีมใช้ Google Sheets เป็นอยู่แล้ว, หลายคนพิมพ์พร้อมกันได้, มีประวัติแก้ไขในตัว, ค่าใช้จ่าย 0 บาท

ข้อจำกัดที่ต้องรู้ล่วงหน้า:

- โควตาส่งเมลของ Apps Script จำกัดต่อวัน และบัญชี Gmail ทั่วไปได้น้อยกว่าบัญชี Google Workspace มาก — ต้องเช็คโควตาจริงของบัญชีที่จะใช้ก่อน (ดูข้อ 5.1)
- Apps Script วาดรูป PNG ตรง ๆ ไม่ได้ ต้องอ้อมผ่าน Google Slides แล้ว export เป็น PNG (ดูวิธีในข้อ 5.2)
- ตรรกะซับซ้อนขึ้นเมื่อไหร่ Apps Script จะเริ่มดูแลยาก

### เฟส 2 — เว็บแอปของตัวเอง (ทำเมื่อเฟส 1 ชนเพดาน)

```
Next.js (หน้าจอจดประชุมแบบตาราง พิมพ์แล้วเซฟอัตโนมัติ)
   └─ Postgres / Supabase (meetings, action_items, users)
        ├─ Resend หรือ SES        → อีเมล HTML
        ├─ LINE Messaging API     → Flex Message + รูป PNG
        ├─ Puppeteer หรือ satori   → เรนเดอร์ HTML เป็น PNG
        └─ cron รายวัน            → เตือนงานใกล้ครบกำหนด / เลยกำหนด
```

สิ่งที่ได้เพิ่มจริง ๆ คือ การติดตามสถานะงานข้ามประชุม, การเตือนอัตโนมัติ, และหน้าจอที่พิมพ์เร็วกว่าชีต — ถ้ายังไม่ต้องการ 3 อย่างนี้ อย่าเพิ่งทำ

### เฟส 3 — ถอดเสียงประชุมเป็นร่าง MOM

อัดเสียง → ถอดข้อความ → ให้โมเดลร่าง Action items → **คนตรวจแก้ก่อนส่งเสมอ** ห้ามส่งร่างที่ AI ทำโดยไม่มีคนอ่าน เพราะชื่อคนและวันที่คือจุดที่โมเดลพลาดบ่อยที่สุด

## 5. รูปแบบผลลัพธ์ที่ส่งออก

### 5.1 อีเมล (ช่องทางหลัก เพราะใช้อ้างอิงย้อนหลังได้)

- **Subject:** `[MOM] <ชื่อประชุม> — <วันที่> (<จำนวน> action items)`
- **Body:** หัวเรื่อง → มติที่ประชุม → ตาราง action items เรียงตาม `due_date` → ประเด็นค้าง → นัดครั้งถัดไป
- แนบ PDF ฉบับเต็ม และไฟล์ `.ics` ของนัดครั้งหน้า (ทางเลือก)
- **เทคนิคที่ได้ผล:** ส่งเมลรวมให้ทุกคน แล้วส่งเมลแยกรายบุคคลที่มีเฉพาะงานของคนนั้น อัตราการทำตามสูงกว่าชัดเจน
- **โควตา:** `GmailApp`/`MailApp` มีเพดานจำนวนผู้รับต่อวัน และบัญชี Gmail ทั่วไปได้น้อยกว่า Google Workspace หลายเท่า ก่อนเลือกบัญชี ให้เปิดหน้า Apps Script quotas เช็คตัวเลขปัจจุบัน แล้วคูณด้วย (จำนวนประชุมต่อวัน × จำนวนผู้รับ + เมลรายบุคคล) — ถ้าใช้บัญชีส่วนตัวและยังเกิน ให้ตัดเมลรายบุคคลออกเหลือเมลรวมฉบับเดียว

### 5.2 LINE กลุ่ม — สร้างรูป PNG แล้วเซฟไปวางเอง (ทางที่เลือกใช้ในเฟส 1)

ไม่ต้องมี LINE OA ไม่ต้องมีบอท ไม่มีโควตาข้อความ ไม่มีความเสี่ยงส่งผิดกลุ่ม แลกกับการที่คนต้องกดเซฟรูปแล้ววางในกลุ่มเอง ประมาณ 10 วินาที

**วิธีสร้าง PNG จาก Apps Script (Apps Script วาดรูปเองไม่ได้):**

1. (ทางเลือก) เตรียม **Google Slides หนึ่งไฟล์เป็นเทมเพลต** ขนาดแนวตั้งประมาณ 1080 × 1350 px วาง text box พร้อม placeholder `{{TITLE}}`, `{{HEADLINE}}`, `{{COUNT}}`, `{{ITEMS}}`, `{{FOOTER}}`
   ถ้าไม่ตั้งเทมเพลต สคริปต์จะวาดสไลด์แนวนอน 16:9 ให้เองโดยไม่ต้องเตรียมไฟล์อะไรเลย
2. ตอนกดปุ่ม ให้สคริปต์ copy เทมเพลต → แทนที่ placeholder ด้วยข้อมูลจริงด้วย `replaceAllText()`
3. Export สไลด์เป็น PNG ผ่าน Slides API (`presentations.pages.getThumbnail` ตั้ง `thumbnailSize` เป็นค่าสูงสุด) แล้วดึงไฟล์มาเก็บใน Drive โฟลเดอร์ `MOM/images/`
4. ลบไฟล์สไลด์ชั่วคราวทิ้ง แล้วเด้ง dialog พร้อมลิงก์รูป ให้ผู้จดกดเซฟไปวางในกลุ่ม LINE

**ข้อจำกัดที่ต้องออกแบบเผื่อ:** ความละเอียดของ thumbnail มีเพดาน และรูปเดียวใส่งานได้จำกัด ถ้ามี action items เกิน ~8 รายการ ให้รูปแสดงเฉพาะ **5 อันดับแรกตามกำหนดเสร็จ** แล้วเขียนท้ายรูปว่า "และอีก N รายการ — ดูรายละเอียดในอีเมล" อย่าย่อฟอนต์จนอ่านไม่ออก

**ทางเลือกที่ง่ายกว่านี้อีก** ถ้าไม่อยากทำเทมเพลตสไลด์: ให้สคริปต์สร้างข้อความสั้นตามข้อ 5.3 แล้วเปิด dialog ให้กดปุ่ม "คัดลอกข้อความ" เอาไปวางใน LINE เป็นตัวหนังสือ ทำเสร็จใน 30 นาที และค้นหาข้อความย้อนหลังในกลุ่มได้ ต่างจากรูปภาพที่เสิร์ชไม่เจอ

**ถ้าวันหนึ่งอยากให้ส่งเข้ากลุ่มอัตโนมัติ** ต้องใช้ LINE Messaging API (`POST https://api.line.me/v2/bot/message/push`) ซึ่งต้องสร้าง LINE OA, เชิญบอทเข้ากลุ่ม, เก็บ `groupId` จาก webhook และเก็บ access token ไว้ใน Script Properties
หมายเหตุสำคัญ 2 ข้อ: **LINE Notify ปิดบริการไปแล้วเมื่อ 31 มี.ค. 2025** อย่าไปทำตามบทความเก่า และการส่งรูปผ่าน API ต้องมี public HTTPS URL ของไฟล์ (ลิงก์แชร์ Google Drive ใช้ไม่ได้ ต้องมี R2/S3) — ตอนนั้น Flex Message จะง่ายกว่าการส่งรูปมาก

## 6. เรื่องที่มักพลาด (อ่านก่อนเริ่มเขียนโค้ด)

| ความเสี่ยง | ผลที่เกิด | วิธีกัน |
| --- | --- | --- |
| กดปุ่มส่งสองครั้ง | ผู้รับได้อีเมลซ้ำ | เช็ค `status = sent` และ `sent_at` ก่อนส่งทุกครั้ง |
| ส่งอีเมลผิดคนตอนทดสอบ | ข้อมูลภายในรั่ว | มีโหมด `DRY_RUN` ที่พิมพ์ผลลัพธ์ลง log แทนการส่งจริง และตั้งเป็นค่าเริ่มต้น |
| รูปที่สร้างยังเป็นของประชุมเก่า | วางรูปผิดครั้งในกลุ่ม | ใส่ `meeting_id` และวันที่ลงบนรูปเสมอ และตั้งชื่อไฟล์เป็น `MOM-2026-001.png` |
| งานเยอะจนรูปแน่น | อ่านไม่ออกบนมือถือ | รูปแสดง 5 อันดับแรก ที่เหลือเขียนว่า "และอีก N รายการ" |
| Token หลุดขึ้น repo (ถ้าวันหนึ่งต่อ LINE API) | ใครก็ส่งข้อความเข้ากลุ่มได้ | เก็บใน Script Properties หรือ `.env` และใส่ `.gitignore` |
| ชื่อคนสะกดไม่ตรงกันแต่ละครั้ง | ติดตามงานรายคนไม่ได้ | ใช้ dropdown จากทะเบียนรายชื่อ ห้ามพิมพ์มือ |
| รูปแบบวันที่ไม่นิ่ง | เตือนผิดวัน | บังคับ `YYYY-MM-DD` ที่ระดับ data validation |
| ไม่มีใครอัปเดตสถานะงาน | MOM กลายเป็นแค่บันทึก | ส่งลิงก์ให้กดอัปเดตสถานะจากมือถือได้ + เตือนก่อนครบกำหนด 1 วัน |
| PDPA / ข้อมูลส่วนบุคคล | ส่งอีเมลผิดคน หรือเก็บข้อมูลเกินจำเป็น | เก็บเฉพาะชื่อและอีเมลที่จำเป็น ตรวจรายชื่อผู้รับก่อนส่งทุกครั้ง |

## 8. สถานะการตัดสินใจ

| ประเด็น | สถานะ |
| --- | --- |
| ช่องทาง LINE | **ตัดสินใจแล้ว** — สร้างรูป PNG ให้ แล้วคนเซฟไปวางในกลุ่มเอง ไม่ต่อ LINE API ในเฟสนี้ |
| บัญชีที่ใช้ส่งอีเมล | **ยังไม่สรุป** — ผู้ใช้จะไปเช็คว่าเป็น Gmail ส่วนตัวหรือ Google Workspace โค้ดจะเขียนให้ใช้ได้ทั้งสองแบบ ต่างกันแค่การเปิด/ปิดเมลรายบุคคลตามโควตา |
| เก็บ MOM ย้อนหลังที่ไหน / กี่ปี | ยังไม่สรุป ค่าเริ่มต้นคือเก็บในชีตเดียวกันและไฟล์ใน Drive |
| ทะเบียนรายชื่อ + อีเมลของทีม | ต้องขอจากผู้ใช้ตอนตั้งค่า ไม่เก็บใน repo |
