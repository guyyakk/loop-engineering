# Retro log

บันทึกทุกครั้งที่ loop ไม่จบแบบราบรื่น เงื่อนไขที่ต้องบันทึกอยู่ในหัวข้อ "Retro" ของ [LOOP_WORKFLOW.md](LOOP_WORKFLOW.md): ครบ 3 รอบแก้, ติด blocker, มีข้อ "ตรวจโดยคน", หรือ `Not run` ด้วยเหตุผลเดิมซ้ำจาก spec ก่อน
เป้าหมายคือเห็น pattern แล้วปรับ [LOOP_WORKFLOW.md](LOOP_WORKFLOW.md) หรือ templates ให้ตรงกับของจริงของทีม ไม่ใช่เก็บไว้เฉย ๆ

## วิธีใช้

1. เพิ่มแถวใหม่ก่อนจบ spec ทุกครั้งที่เข้าเงื่อนไขข้างต้น อ้างอิง task spec ที่เกี่ยวข้อง
2. ทุกไตรมาส (หรือเมื่อแถวเริ่มเยอะ) อ่านทวนทั้งตาราง หา pattern ที่ซ้ำ ๆ แล้วแก้ที่ต้นเหตุ (เช่น เกณฑ์รับงานที่เขียนกว้างเกินไปเป็นประจำ, technology ที่ verify ยากเป็นพิเศษ)
3. คอลัมน์ "การปรับกติกา" ต้องจบที่ "ปรับแล้ว (ไฟล์ที่แก้)" หรือ "ไม่ปรับ (เหตุผล)" ภายใน spec ถัดไป — "ยังไม่ปรับ" ค้างไว้นานคือสัญญาณว่ากระบวนการไม่เรียนรู้

เงื่อนไข ครบ 3 รอบ / ติด blocker / มีข้อตรวจโดยคน ถูกตรวจด้วย `node scripts/check-docs.mjs` ใน CI แล้ว ส่วน `Not run` ที่เหตุผลซ้ำและข้อเสนอที่ค้างยังต้องดูเอง
