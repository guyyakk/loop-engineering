# วิธีติดตั้ง MOM Apps Script

สคริปต์ชุดนี้ผูกกับ Google Sheet หนึ่งไฟล์: จดประชุมผ่านฟอร์มหน้าเดียว → ตรวจข้อมูล → ส่งอีเมลสรุป → สร้างรูป PNG สำหรับวางในกลุ่ม LINE
ที่มาของการออกแบบอยู่ที่ [docs/MOM_SYSTEM_DESIGN.md](../docs/MOM_SYSTEM_DESIGN.md)

## ไฟล์ในโฟลเดอร์นี้

| ไฟล์ | หน้าที่ |
| --- | --- |
| `FormUi.html` | **หน้าฟอร์มจดประชุม** — หน้าหลักที่ใช้งานจริง |
| `Form.gs` | ฝั่งเซิร์ฟเวอร์ของฟอร์ม: โหลดข้อมูลเข้าฟอร์มและบันทึกกลับชีต |

| `Setup.gs` | สร้างชีต 3 ชีตพร้อม dropdown กฎตรวจข้อมูล สีเตือนงานเลยกำหนด และอัปเกรดคอลัมน์ใหม่ให้ชีตเดิม |
| `Data.gs` | อ่านข้อมูลจากชีตและตรวจความถูกต้องก่อนส่ง |

| `Image.gs` | สร้าง PNG สรุปฉบับเต็มผ่าน Google Slides แล้วเก็บลง Drive |
| `Menu.gs` | เมนู "MOM" ในชีต (ทางเลือกสำรอง) |
| `Log.gs` | บันทึก error ลงชีต `log` และคุมว่าใครเรียกฟังก์ชันของ Web App ได้ |
| `WebApp.gs` | `doGet` เสิร์ฟฟอร์มเป็น Web App + ขั้นตอนปิดประชุมแบบไม่ใช้ dialog ของชีต |
| `Build.gs` | ประทับเวลาที่ deploy ล่าสุด — `tools/deploy.ps1` เขียนทับให้เอง อย่าแก้มือ |
| `tools/verify.js` | ตรวจทุกอย่างก่อน deploy ด้วยคำสั่งเดียว |
| `tools/deploy.ps1` | ตรวจ → ประทับเวอร์ชัน → push → deploy ทับ deployment เดิม |
| `tests/smoke.js` | เทสต์ฟังก์ชันบริสุทธิ์ (validation, การจัดรูปแบบ, เนื้อหาในรูป) |
| `tests/sheet_smoke.js` + `tests/fake_sheets.js` | เทสต์ชั้นที่คุยกับชีต ด้วย SpreadsheetApp ปลอมในหน่วยความจำ |
| `tests/image_mock.html` | แบบจำลองเลย์เอาต์ของรูปสรุป ใช้ตอนออกแบบ ไม่ได้ถูก push ขึ้น Apps Script |
| `tests/make_preview.py` | สร้างไฟล์พรีวิวที่ stub `google.script.run` ไว้ทดสอบ UI ในเบราว์เซอร์ก่อน deploy |
| `appsscript.json` | manifest — timezone และการเปิด Advanced Slides Service |

## ติดตั้ง (ประมาณ 10 นาที)

1. สร้าง Google Sheet ใหม่ ตั้งชื่อเช่น `MOM 2026`
2. เมนู **ส่วนขยาย (Extensions) → Apps Script**
3. ในตัวแก้ไข Apps Script สร้างไฟล์ตามรายการข้างบน แล้ววางเนื้อหาจากโฟลเดอร์นี้ทีละไฟล์
   (ตัวแก้ไขจะแสดงนามสกุลเป็น `.gs` เอง ไม่ต้องพิมพ์นามสกุล)
4. เปิด **Services (+) → Google Slides API → Add** — จำเป็นสำหรับการสร้างรูป
   ถ้าใช้ `clasp` push ทั้งโฟลเดอร์ ขั้นนี้ทำให้อัตโนมัติจาก `appsscript.json` แล้ว
5. แก้ `appsscript.json` ให้ `timeZone` ตรงกับที่ใช้จริง (ค่าเริ่มต้นคือ `Asia/Bangkok`)
6. กด **Save** แล้วกลับไปที่ชีต **โหลดหน้าใหม่** จะเห็นเมนู **MOM** โผล่ขึ้นมา
7. สั่ง **MOM → ⚙ ตั้งค่าเริ่มต้น (สร้าง/ซ่อมชีต)** — ครั้งแรกจะขึ้นหน้าขออนุญาตสิทธิ์ ให้กดอนุญาต
8. กรอกชื่อและอีเมลทีมในชีต `people` แล้วลบสองแถวตัวอย่างทิ้ง

> ครั้งแรกที่รัน Google จะเตือนว่าแอปยังไม่ผ่านการตรวจสอบ ให้กด Advanced → Go to (ชื่อโปรเจกต์)
> เป็นเรื่องปกติของสคริปต์ที่เขียนเอง เพราะเจ้าของสคริปต์คือบัญชีของคุณเอง

## แก้โค้ดแล้วเอาขึ้นยังไง

```powershell
.	ools\deploy.ps1 "อธิบายสั้น ๆ ว่าแก้อะไร"
```

สคริปต์เดียวจบ: ตรวจ → ประทับเวอร์ชันลง `Build.gs` → `clasp push` → `clasp deploy` **ทับ deployment เดิม**
(หา deploymentId ให้เอง จึงไม่มีทางเผลอสร้าง deployment ใหม่ ซึ่งจะทำให้ URL เปลี่ยน)
ถ้าตรวจไม่ผ่าน สคริปต์จะหยุดก่อน push

ตรวจอย่างเดียวไม่ deploy:

```bash
node tools/verify.js
```

ตรวจ 5 อย่าง: คอมไพล์ `.gs` ทุกไฟล์ · คอมไพล์ JavaScript ใน `FormUi.html` ·
**ทุกปุ่มมีฟังก์ชันรองรับจริง** · เทสต์ฟังก์ชันบริสุทธิ์ · เทสต์ชั้นที่คุยกับชีต

> ข้อ "ทุกปุ่มมีฟังก์ชันรองรับจริง" เพิ่มมาเพราะเคยพลาดจริง: รีแฟกเตอร์แล้วลบฟังก์ชันทิ้ง
> แต่ปุ่มยังเรียกอยู่ กดแล้วเงียบไปเฉย ๆ การคอมไพล์จับไม่ได้เพราะ `onclick` ผูกตอนรัน

ทดสอบหน้าจอโดยไม่ต้อง deploy (ได้ไฟล์ที่เปิดในเบราว์เซอร์ธรรมดาแล้วกดปุ่มจริงได้):

```bash
python tests/make_preview.py
```

หลัง deploy หน้าเว็บจะโชว์ "เวอร์ชัน YYYY-MM-DD HH:mm" ที่แถบล่าง ใช้ยืนยันว่าผู้ใช้ refresh แล้วจริง

## ค่าตั้งค่า (Script Properties)

ตั้งที่ Apps Script → **Project Settings → Script Properties** ไม่ต้องแก้โค้ด

| Key | ค่าเริ่มต้น | ความหมาย |
| --- | --- | --- |
| `DRY_RUN` | `true` | `true` = ไม่ส่งอีเมลจริง แค่เขียน log — **เปลี่ยนเป็น `false` เมื่อพร้อมใช้จริงเท่านั้น** |
| `SEND_INDIVIDUAL` | `false` | `true` = ส่งเมลแยกให้แต่ละคนเฉพาะงานของตัวเองด้วย |
| `CC_EMAILS` | ว่าง | อีเมลผู้รับสำเนา คั่นด้วย `,` |
| `SENDER_NAME` | `MOM Bot` | ชื่อผู้ส่งที่แสดงในอีเมล |
| `SLIDE_TEMPLATE_ID` | ว่าง | ว่าง = วาดสไลด์แนวนอนให้เอง / ใส่ ID ไฟล์สไลด์ = ใช้เทมเพลตของคุณ |
| `IMAGE_FOLDER_ID` | ว่าง | ว่าง = สร้างโฟลเดอร์ `MOM images` ให้อัตโนมัติแล้วจำ ID ไว้เอง |
| `MAX_ITEMS_IN_IMAGE` | `0` | `0` = แสดงทุกงาน / ใส่ตัวเลข = จำกัดจำนวนงานในรูปและข้อความ LINE |
| `USE_BUDDHIST_YEAR` | `false` | `true` = แสดงปี พ.ศ. |
| `MIN_TASK_LENGTH` | `0` | `0` = ไม่จำกัดความยาวชื่องาน / ใส่ตัวเลข = เตือน (ไม่บล็อก) เมื่อสั้นกว่านั้น |
| `SUMMARY_LINK` | ว่าง | ลิงก์สรุปฉบับเต็ม ต่อท้ายข้อความ LINE |

สลับ `DRY_RUN` ได้ 2 ทาง โดยไม่ต้องเข้าหน้า settings:
- **ในหน้า Web App** — ป้ายโหมดที่แถบล่าง กด "เปลี่ยนเป็นส่งจริง" แล้วยืนยัน
- ในชีต — เมนู **MOM → ⚙ สลับโหมดทดสอบ / ส่งจริง**

ป้ายโหมดจะเตือนด้วยถ้าไม่มีใครในชีต `people` ที่กรอกอีเมลไว้ เพราะกรณีนั้นระบบจะข้ามการส่งเมล
(แต่ยังสร้างรูปและข้อความ LINE ให้ตามปกติ)

## ใช้งานประจำวัน

> **ทางหลักคือลิงก์ Web App** — เปิดลิงก์เดียวจบ ไม่ต้องเปิดชีตและไม่ต้องใช้เมนู
> ลิงก์ได้จาก `clasp deploy` หรือ Apps Script editor → Deploy → Manage deployments
> เมนู MOM ในชีตเป็นทางเลือกสำรอง และต้องการสิทธิ์ `script.container.ui` เพิ่ม

**ไม่ต้องกรอกในชีตเอง** — ใช้ฟอร์มอย่างเดียวก็พอ ชีตเป็นแค่ที่เก็บข้อมูลเบื้องหลัง

1. **MOM → 📝 จดประชุม (เปิดฟอร์ม)** — ฟอร์มจะเปิดร่างล่าสุดที่ยังไม่ได้ส่งขึ้นมาให้ ถ้าไม่มีก็เริ่มใหม่ของวันนี้
2. กรอกชื่อประชุม เวลา สถานที่ → **กดชื่อผู้เข้าร่วม** ซึ่งแยกเป็นกลุ่มตามแผนก
   ถ้ามีคนมาร่วมที่ยังไม่อยู่ในทะเบียน กด **"+ มีคนมาเพิ่ม พิมพ์ชื่อเข้าไปเลย"** ได้จากหน้านี้
   (ชื่อบังคับ · แผนกและอีเมลไม่บังคับ · คนที่เพิ่มถูกบันทึกลงชีต `people` จริง จึงรับงาน
   และรับอีเมลได้ในครั้งต่อ ๆ ไป · ชื่อซ้ำจะไม่สร้างแถวใหม่ และคนที่ปิดใช้งานไว้จะถูกเปิดกลับ)
   (กดหัวแผนกเพื่อพับ/กาง มีปุ่ม "เลือกทั้งแผนก" และหัวกลุ่มบอกจำนวนที่เลือกไว้แม้พับอยู่)
   จากนั้นกรอก **วาระการประชุม** บรรทัดละ 1 วาระ
3. ระหว่างประชุมพิมพ์งานในตาราง: ทำอะไร / ต้องใช้อะไร / ใคร (dropdown) / เสร็จเมื่อไหร่
   แถวใหม่จะหยิบกำหนดเสร็จของแถวก่อนหน้ามาให้ กด **+ เพิ่มงาน** เพื่อเพิ่มแถว
4. กด **บันทึกร่าง** เป็นระยะ (หรือกด **บันทึกแล้วตรวจ** เพื่อดูว่ายังขาดอะไร)
5. ปิดฟอร์ม แล้วสั่ง **📧 ส่งอีเมลสรุป** → อ่าน dialog ยืนยัน (บอกจำนวนผู้รับและโหมดที่ใช้อยู่) แล้วกด Yes
6. แผงผลลัพธ์จะแสดง **รูปสรุปเต็ม ๆ ในหน้าเลย** — มือถือกดค้างที่รูป → บันทึกรูปภาพ / คอมคลิกขวา → Save image as
   แล้ววางในกลุ่ม LINE หรือใช้ปุ่ม **คัดลอกข้อความ** ถ้าอยากวางเป็นตัวหนังสือ (ค้นหาย้อนหลังในกลุ่มได้)
7. จบประชุมแล้วกด **เริ่มประชุมใหม่ (ล้างฟอร์ม)** ในแผงผลลัพธ์ ระบบจะสร้างรหัสประชุมถัดไปให้
   ประชุมที่เพิ่งปิดยังอยู่ในชีตครบ ไม่ถูกลบ

> ปุ่มเริ่มประชุมใหม่จำเป็นเพราะในโหมดทดสอบสถานะยังเป็น `draft` ถ้าไม่กด ระบบจะดึงร่างเดิม
> กลับมาให้แก้ต่อทุกครั้งที่เปิดฟอร์ม

เมนู **🔍 ตรวจข้อมูลก่อนส่ง** และ **➕ เพิ่มการประชุมใหม่** ยังอยู่ สำหรับคนที่อยากทำงานในชีตตรง ๆ
ถ้าเผลอไปกรอกในชีต เอาเมาส์ชี้ที่หัวคอลัมน์จะมีคำอธิบายว่าช่องนั้นใส่อะไร

## สิ่งที่ระบบกันไว้ให้เอง

| กรณี | สิ่งที่ระบบทำ |
| --- | --- |
| มีคนสลับคอลัมน์ในชีต | การเขียนอิง **ชื่อ** คอลัมน์เสมอ ไม่ใช่ตำแหน่ง ข้อมูลจึงไม่ลงผิดช่อง |
| ชีตเวอร์ชันเก่าขาดคอลัมน์ท้ายตาราง | เติมให้เองตอนใช้งานครั้งแรก ไม่ต้องสั่งเมนู |
| หัวตารางผิดรูปแบบจริง ๆ | ปฏิเสธพร้อมบอกชื่อคอลัมน์ที่ขาด ไม่เขียนมั่ว |
| เปิดฟอร์ม 2 แท็บแล้วบันทึกทับกัน | ตรวจ `updated_at` แล้วถามก่อนว่าจะทับหรือไม่ (ไม่ทับเงียบ ๆ) |
| ชื่อ/อีเมลในชีตมีอักขระ HTML | escape ก่อนแสดงผลทุกจุด สคริปต์ที่ฝังมาไม่ทำงาน |
| Slides API หรือการดาวน์โหลดรูปสะดุด | ลองใหม่ 3 ครั้งแบบหน่วงเพิ่มขึ้น ก่อนยอมแพ้ |
| ส่งอีเมลไม่ได้ | ยังสร้างรูปและข้อความ LINE ให้ตามปกติ |
| เกิด error กับผู้ใช้ | บันทึกลงชีต `log` (เวลา · ผู้ใช้ · ฟังก์ชัน · ข้อความ) เก็บ 500 บรรทัดล่าสุด |
| ชีต `people` มีชื่อซ้ำกัน | เตือนในฟอร์ม เพราะระบบใช้ชื่อเป็นตัวระบุตัวตน งานอาจถูกส่งไปผิดคน |

## ถ้าจะเปิดให้ทีมใช้ด้วย

ตอนนี้ `webapp.access` เป็น `MYSELF` คือเปิดได้เฉพาะเจ้าของ ถ้าจะให้ทีมใช้:

1. แก้ `appsscript.json` เป็น `"access": "ANYONE"` แล้ว deploy ใหม่
2. กรอกอีเมลของทุกคนที่จะใช้ลงในชีต `people` ให้ครบ

ระบบมีด่านตรวจสิทธิ์ (`assertAllowed_`) อยู่แล้ว: **เจ้าของผ่านเสมอ · คนที่มีอีเมลอยู่ในชีต
`people` และยัง active ผ่าน · นอกนั้นถูกปฏิเสธ** ด่านนี้จำเป็น เพราะ Web App รันด้วยสิทธิ์
ของเจ้าของ ถ้าไม่มีด่าน ใครมีลิงก์ก็เขียนข้อมูลและสั่งส่งอีเมลจากบัญชีเจ้าของได้

## กฎที่ระบบบังคับ (แก้ไม่ได้จนกว่าจะแก้ข้อมูล)

- `task` ต้องไม่ว่าง (ไม่จำกัดความยาว — ถ้าอยากให้เตือนเมื่อสั้นเกินไป ตั้ง `MIN_TASK_LENGTH` เป็นตัวเลข ระบบจะเตือนแต่ไม่บล็อก)
- `owner` ต้องมี ต้องอยู่ในชีต `people` และต้องเป็นคนเดียว (มี `,` `/` `และ` `กับ` จะไม่ผ่าน)
- `due_date` ต้องมี และต้องไม่ย้อนหลังกว่าวันประชุม
- ประชุมที่ `status = sent` แล้วจะส่งอีเมลซ้ำไม่ได้ ต้องล้าง `status` และ `sent_at` เองก่อน

## รูปสรุปมีอะไรบ้าง

รูปเดียวมีครบทั้งบันทึกการประชุม เรียงตามลำดับสายตา:

| ส่วน | เนื้อหา |
| --- | --- |
| หัวรูป | ชื่อประชุม (ตัวใหญ่สุด) · วันที่ · เวลาเริ่ม–จบ · สถานที่ |
| แถวบทบาท | ประธาน · ผู้จดบันทึก · จำนวนผู้เข้าร่วม |
| ผู้เข้าร่วม | ชื่อทุกคน (และคนที่ไม่เข้าร่วม ถ้ามี) |
| วาระ / มติ | ตามที่กรอกในฟอร์ม |
| **ตารางสิ่งที่ต้องทำ** | `#` · **ทำอะไร** (+ "ต้องใช้อะไร" บรรทัดย่อย) · **ใคร** · **ครบกำหนด** (สีแดง) |
| ประเด็นค้าง | ถ้ามี |
| ท้ายรูป | ประชุมครั้งถัดไป · รหัสประชุม |

**ขนาดตัวหนังสือคงที่ ไม่ย่อตามปริมาณเนื้อหา** — Slides export รูปที่ความกว้าง 1600px เสมอ
ระบบจึงคำนวณความสูงของผืนผ้าใบจากเนื้อหาแทนการย่อฟอนต์ ประชุมที่มีงานเยอะจะได้รูปที่ยาวขึ้น
แต่ตัวหนังสือใหญ่เท่าเดิม (ตัวงาน 12.5pt บนผืนผ้าใบ 480pt ≈ 42px ในไฟล์จริง)

ถ้าเนื้อหายาวเกิน `CANVAS_MAX_H` หรือ Slides API ไม่ยอมกำหนดขนาดผืนผ้าใบ ระบบจะย่อสเกลลง
ก่อน แล้วค่อยตัดจำนวนงานเป็นทางเลือกสุดท้าย พร้อมเขียนว่า "และอีก N รายการ"

แบบจำลองเลย์เอาต์อยู่ที่ `tests/image_mock.html` — เปิดในเบราว์เซอร์เพื่อดูสัดส่วนก่อนแก้โค้ดวาดรูป

## อยากได้รูปแนวตั้งสำหรับมือถือ

1. สร้าง Google Slides ไฟล์ใหม่ → **ไฟล์ → ตั้งค่าหน้า → กำหนดเอง** ใส่ `19.05 x 23.81 ซม.` (≈ 1080×1350 px)
2. วางกล่องข้อความที่มีคำเหล่านี้: `{{TITLE}}`, `{{HEADLINE}}`, `{{ATTENDEES}}`, `{{AGENDA}}`,
   `{{DECISIONS}}`, `{{COUNT}}`, `{{ITEMS}}`, `{{ISSUES}}`, `{{FOOTER}}`
3. ก๊อป ID ของไฟล์จาก URL (`/presentation/d/<ID>/edit`) ไปใส่ใน Script Property `SLIDE_TEMPLATE_ID`

สคริปต์จะคัดลอกเทมเพลตแล้วแทนที่ข้อความให้เอง โดยไม่แตะไฟล์ต้นฉบับ

## ขยายต่อในอนาคต

- **เตือนก่อนครบกำหนด**: เพิ่ม time-driven trigger รายวัน อ่าน `action_items` ที่ `status != Done` และ `due_date` เหลือ 1 วัน แล้วส่งเมลถึง owner
- **ส่งเข้ากลุ่ม LINE อัตโนมัติ**: ต้องใช้ LINE Messaging API (สร้าง LINE OA + เชิญบอทเข้ากลุ่ม + เก็บ `groupId` จาก webhook) — เก็บ token ใน Script Properties เท่านั้น และอย่าใช้ LINE Notify เพราะปิดบริการไปแล้วเมื่อ 31 มี.ค. 2025
